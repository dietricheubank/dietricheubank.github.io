Engineering case study

Forge: building a reliable local AI appliance

A public case study of engineering decisions from a dual-node NVIDIA GB10 local AI experiment, without revealing private operational configuration.

The problem

Proving that distributed inference works is not the same as operating a system reliably. The objective was to make local AI simple to use: start the hardware, allow services to recover automatically, and access consistent Fast and Deep experiences from a browser.

Architecture

The documented system uses two ASUS GX10 / NVIDIA GB10 devices for distributed model inference. A browser interface routes through Open WebUI and LiteLLM to the TensorRT-LLM runtime. GPU telemetry feeds Prometheus and Grafana.

Engineering decisions

One validated inference path

Keep the primary model runtime stable rather than proliferating services and model versions.

Separate failure domains

Diagnose model health, service health, local access and remote access independently.

Design for reboot recovery

Supervise long-running services and verify inter-node readiness, not just interactive success.

Lessons learned

Runtime compatibility is hardware-specific; newer packages are not automatically better. Multiple network interfaces on the same cluster subnet can confuse distributed-communication libraries even when ordinary connectivity appears healthy. A successful interactive session does not prove unattended restart reliability.

Validation and limitations

Public documentation records multi-node inference, model-serving routes and monitoring milestones. A complete two-node power-cycle acceptance test was identified as further work; it should not be portrayed as already completed. The case study presents architecture and observed lessons rather than a turnkey installer or a guaranteed performance specification.
